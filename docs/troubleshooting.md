# Неисправности

| Симптом | Проверка / действие |
|---|---|
| GPIO/SDA около5В | **Отключить питание**. LCD через BSS138, проверить LV/HV и подтяжки; не лечить прошивкой |
| I²C timeout/NACK | питание чипа/земля/провода, параллельные pull-ups, адресAD0, качество фронтов. Внутренних pull-ups недостаточно для надёжной400кГц |
| WHO_AM_I не 0x68 | Проверить реальный чип/адрес. Нельзя принять любой ACK за MPU-6050 |
| VERIFY reg=... got!=expected | конфигурация не подтверждена, sensor_ok=false и нетsamples. Проверить питание/модель/шину; не обходить проверку и не генерироватьнули |
| FIFO_TIMESTAMP_MISMATCH / IRQ overflow | проверитьGPIO27/INT и реальные фронты, наводки, I²C/нагрузку, counters. Участок отброшен; timestamps не угаданы |
| DATA_READY_TIMEOUT | Проверить INT, настройку и питание; после исправления явный set_config вне опыта или restart |
| LCD не найден / несколько ACK | Отдельная I²C1, только 0x20..27/38..3F, адрес не угадывать. Осмотр PCF/документации и LCD_ADDRESS override |
| LCD подсвечен, но нет букв | Контраст, питание, действительные pin mapping/BL polarity. ACK/init не доказывают разводку. Страница 4 — тест 16×2 |
| LCD ERR | Не препятствует AP/измерениям. RW низкий, generic PCF; иной контроллер требует подтверждённого драйвера, не слепой подстановки |
| После open serial поменялся boot | DTR/RTS reset circuit/драйвер. CLI не делает намеренный reset, но ждёт HELLO; используйте одно меню или Wi-Fi для RAM-кандидатов |
| Нет ответа UART | Не тот порт/baud, занят монитором/esptool, права dialout; 460800 8N1, бинарный COBS, не текст CSV. ROM 115200 отбрасывается |
| Нет HELLO | Дождаться 8 с, проверить firmware/питание/порт. Не замыкать GPIO0/EN для обычной записи |
| «Нет Интернета» в AP | Нормально. Остаться в локальной сети, отключить автопереход на другую AP/прокси для 192.168.4.1. Не включать NAT/облако |
| После смены AP wrong ID | Выбрать свой SSID, сверить номер/UID. Один IP не доказывает идентичность |
| «Не подключено», WebSocket сразу закрывается | Проверить код закрытия в UI, открыть `/api/status`. В используемом SDK handshake не вызывает URI-handler: endpoint должен регистрироваться на первом WS-кадре, а не только при `HTTP_GET`. После прошивки обновить страницу и нажать «Подключить и сверить» |
| INVALID_STATE/BUSY | Активный опыт/мастер. Проверить owner; явно end_experiment с confirm_owner при необходимости, либо cal_cancel. Потеря клиента не завершает опыт |
| GAP после 4 с | Окно RAM включает reconnect/resume; история вытеснена. Не подменять нулями/интерполяцией, разделить интегратор |
| Потери клиента / 4 WS | Проверить heap/minheap/стеки, ACK lease 2,5 с, размеры команд, реальную скорость радио. Медленного отключают, сенсор не перенастраивают |
| Углы «неправильные» | Оси S не обязательно совпадают с платой/USB. Проверить R_BS, det=+1, rad/s и q B→W; не исправлять произвольными сменами знаков q |
| Yaw дрейфует | Ожидаемо без магнитометра. Не объявлять север или эталон Comau; исследовать bias/температуру/интегрирование |
| Нет готовности ориентации | Требуется 1 с подтверждённого покоя; raw доступен. Большой bias сначала калибровать; движение не считать нулевыми углами |
| UNCALIBRATED после рестарта | apply не равно save; NVS version/CRC/UID проверены, повреждённое не применяется. Ошибка NVS не устраняется автоматическим erase |

При диагностике сначала сохраняйте metadata/events/status/логи и отметьте реальные
условия. Не перепрошивайте случайный первый serial port. Не отключайте защитные
проверки только ради красивого графика. Электрические и механические дефекты не
подтверждаются и не исправляются программным ACK.

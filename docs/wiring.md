# Соединения и обязательная проверка человеком

**Это проектная схема, не отчёт об измеренной электрической безопасности.**
GPIO ESP32 — 3,3 В. Успешный ACK/прошивка не проверяют напряжения и монтаж.
Все переподключения — при снятом питании. Манипулятор не запускать из этого ПО.

| Подключение | Куда | Замечание |
|---|---|---|
| MPU SDA | ESP32 GPIO21 | I²C0, 400 кГц, только 3,3 В |
| MPU SCL | ESP32 GPIO22 | I²C0 |
| MPU INT | ESP32 GPIO27 | Data Ready, уровень 3,3 В |
| MPU VCC | 3V3 | Проверить конкретный модуль, регулятор и фактическое питание чипа |
| MPU GND | GND | Общая земля |
| MPU AD0 | GND | 0x68; при 3V3 изменить `MPU_ADDRESS` на 0x69 |
| GPIO25 | LV1 BSS138 | SDA, I²C1 |
| GPIO26 | LV2 BSS138 | SCL, I²C1, 100 кГц |
| HV1 | LCD SDA | Только сторона 5 В |
| HV2 | LCD SCL | Только сторона 5 В |
| LV | 3V3 | Питание низкой стороны преобразователя |
| HV и LCD VCC | Проверенная единая линия USB 5 В | Не GPIO; не любой VIN без проверки |
| LCD GND, GND BSS138 | GND | Общая земля |

```text
USB компьютера (стол) ИЛИ USB пауэрбанка (Comau), никогда оба
   +--- ESP32 DevKit USB --> проверенный 3V3 --> MPU / LV
   +--- проверенное распределение тех же USB 5V --> LCD VCC / HV

ESP32 GPIO21/22 <-- pull-ups к 3V3 --> MPU SDA/SCL
ESP32 GPIO27   <--------------------- MPU INT (3V3)
ESP32 GPIO25/26 <-- pull-ups 3V3 --> LV [BSS138] HV <-- pull-ups 5V --> LCD
Все GND общие. Высокая сторона никогда напрямую не идёт на ESP32.
```

## Детали

ESP32-WROOM-32 DevKit с USB-UART (без PSRAM), MPU-6050, LCD1602 с I²C-переходником,
двухканальный двунаправленный MOSFET-преобразователь open-drain (например BSS138),
провода/разъёмы, механический корпус/крепёж, USB-кабель, один пауэрбанк,
мультиметр. При необходимости — разветвление **единого** USB-питания и корректно
подобранные подтяжки. Резистивный делитель не заменяет преобразователь SDA/SCL.

## До подачи питания

1. По схеме **конкретной DevKit** определить, доступно ли USB 5 В на выводе.
   VIN может быть входом через иной тракт. Не объявлять его гарантированным выходом.
   Если не подтверждено — отдельное распределение той же USB-линии.
2. Осмотреть MPU-модуль: маркировка микросхемы, регулятор, перемычки, подтяжки.
   Некоторые платы с регулятором при входных 3,3 В дают пониженное питание чипа.
   Измерить питание MPU и проверить его допустимость по datasheet.
3. При отключённом питании измерить/оценить уже установленные подтяжки SDA/SCL
   на MPU, LCD и BSS138. Учитывать параллельное сопротивление. Не добавлять резисторы
   вслепую: слишком сильная подтяжка превышает допустимый ток низкого уровня,
   слишком слабая даёт медленный фронт. Внутренние подтяжки ESP32 лишь вспомогательные.
4. Проверить отсутствие КЗ, общую землю, правильные LV/HV и назначение проводов.

## Под питанием, до эксперимента

Человек мультиметром проверяет 3V3, USB 5V, питание самого MPU, уровни покоя
SDA/SCL **на обеих сторонах** BSS138, INT. На выводах ESP32 не должно быть 5 В.
Мультиметр не измеряет фронты: качество 400/100 кГц при сомнениях проверяют
осциллографом/логическим анализатором. После проверки питания устанавливают
контраст потенциометром LCD; включают страницу `lcd page=4`, проверяют 32 символа.

## LCD: неизвестная комплектация

Ссылка заказчика:
<https://www.ozon.ru/product/lcd-displey-1602-zelenyy-s-i2c-modulem-dlya-arduino-nodemcu-stm32-2765985589/>.
Она **не подтверждает** контроллер, адрес или разводку конкретного экземпляра.
Реализован PCF8574/PCF8574A, но ACK не доказывает именно эту модель.

`main/lab_config.h`: `LCD_ADDRESS=0` разрешает выбор только при одном ACK в
0x20–0x27/0x38–0x3F на **отдельной I²C1**. При нескольких ACK LCD отключён до
явного override. `LCD_ADDRESS`, `LCD_RS/RW/E/BL/D4..D7`, полярность подсветки
настраиваются после осмотра. Начальная, **не подтверждённая** разводка:
P0 RS, P1 RW, P2 E, P3 BL, P4..P7 D4..D7. RW всегда низкий, чтения LCD нет.
Статус `lcd_ok` подтверждает только успешные записи I²C/init, а не видимость текста.

## Крепление

Уложить/зафиксировать кабели, исключить натяжение, попадание в подвижные части,
замыкание на корпус, люфт MPU относительно корпуса. Зафиксировать соответствие
осей S и B. На Comau — только пауэрбанк и Wi-Fi; USB компьютера отключён.
Преподаватель отдельно подтверждает массу, крепёж, безопасную зону и допустимость
существующей программы движения. Получение телеметрии не подтверждает крепление.

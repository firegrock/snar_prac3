# Калибровка

Два равноправных пути: мастер модуля и коэффициенты с ПК. Ни один не переписывает
аппаратные offset-регистры MPU. Raw остаётся независимо проверяемым. В активном
обычном опыте изменения запрещены. Для raw мастера используется CALIBRATION,
тот же поток и события начала/граней/кандидата; его можно писать CLI `calibrate`.

## Гироскоп

`cal_gyro` — 30 с, средние/выборочные std в SI в S, температура, число отсчётов.
Параметры длительности — `main/lab_config.h`. Кандидат bias имеет единицы rad/s.
Инженерные критерии `LAB_CAL_*` в `components/lab_core/include/lab_core.h`:
норма a в ±15% g0, норма gyro <=0.35 rad/s,
std каждого a <=0.1 м/с², gyro <=0.015 rad/s, нет насыщения/разрывов/ресинхронизации.
Они **не метрологическая гарантия** и не способны обнаружить всякое медленное
движение/внешнее ускорение. Движение/пропуски -> REJECTED, не «успех».

После `CANDIDATE` можно экспортировать статистику; `cal_apply` отдельно применяет,
`cal_save` отдельно сохраняет NVS. `use_gyro_bias=false` отключает вычитание без
удаления коэффициентов. После применения запишите **новый независимый** неподвижный
проверочный опыт. Не измеряйте качество на той же калибровочной выборке.

`CAL` означает применённый валидированный набор программных коэффициентов,
а не метрологическую аттестацию всех каналов. После gyro master акселерометр
остаётся с прежними коэффициентами; полнота видна по gyro_n, face_n и raw-записям.
Полный путь включает оба мастера.

## Шесть граней акселерометра

`cal_accel`, затем после установки **вверх оси чипа S** подтверждайте cal_face:
0 +X,1 -X,2 +Y,3 -Y,4 +Z,5 -Z. Каждая 5 с. В целевом направлении >=0.85 g0,
по другим осям <=0.25 g0; действуют критерии покоя выше. Грани не повторяются,
комплект из всех шести обязателен. Неверный знак/положение/движение -> отказ;
cancel и повторная установка, не автоматическое угадывание грани.

По номинальным физическим данным u в S:

```text
bias_i  = (mean_plus_i + mean_minus_i)/2           # m/s^2
scale_i = 2*g0/(mean_plus_i - mean_minus_i)         # dimensionless
f_i     = scale_i*(u_i-bias_i)
```

g0=9.80665 м/с² по умолчанию, в metadata. Модель только поосная, **не** оценивает
неортогональность/перекрёстные члены. Нельзя обнулить все каналы в одном положении.

## Обмен и NVS

JSON schema_version=1: device_uid строка, method, axes="S", gyro_units="rad/s",
accel_units="m/s^2", gyro_bias[3], accel_bias[3], accel_scale[3], temperature_c,
gyro_std[3], gyro_n, face_mean[6][3], face_std[6][3], face_n[6], диапазоны,
firmware_version. Импорт проверяет структуру, конечность, UID, |gyro_bias|<=0.5,
|accel_bias|<=5, 0.5<=scale<=1.5. Чужой UID только явный confirm_transfer.
Оси/единицы обязательны: неоднозначные коэффициенты LSB не принимаются.

NVS blob имеет версию, размер, CRC и проверку коэффициентов/UID. Недоступная,
несовместимая/повреждённая NVS **не очищается автоматически**, применяются безопасные
нулевые bias/единичные scale, статус UNCALIBRATED с причиной. Номер комплекта
берётся исключительно из сборки. В цикле измерения flash не пишется. Явный save
может вызвать задержку flash; она не маскируется и может потребовать ресинхронизации.

Числовой CSV для Octave: одна строка заголовка, затем
`gbx,gby,gbz,abx,aby,abz,asx,asy,asz,temperature_c`. Он **не содержит UID**:
конвертер ПК требует базовый JSON конкретной платы и никогда не выводит UID из
double. При внешнем расчёте сохраняйте исходные записи и статистику вместе с новым
JSON. Отсутствующая исходная статистика не становится измеренной от наличия нулей.

# Архитектура, время и ресурсы

`components/lab_core` — переносимые числовые C: преобразования, Mahony,
калибровочный автомат, compact ring, явный wire codec, command policy/cache,
проверка NVS blob. `main/sensor.c` — I²C0/FIFO/IRQ; `lcd.c` — только I²C1;
`commands.c` — один JSON-диспетчер; `json_model.c` — схемы/валидаторы;
`transport.c` — SoftAP/HTTPD, независимые cursors UART/WS. `app.c` — состояние,
события и NVS. Веб — встроенные файлы без CDN. Python и Octave — отдельные клиенты.

## Временная целостность

MPU reset, sleep off, PLL gyro X, enable всех каналов, FS/DLPF/divider, readback
критичных регистров; FIFO accelXYZ/temp/gyroXYZ =14 байт. IRQ rising DRDY
фиксирует **только esp_timer_get_time и отправку int64 в bounded очередь**.
В ISR нет I²C, фильтра, JSON, printf, malloc. Overflow очереди считается явно.
GPIO ISR IRAM, данные очереди — внутренняя RAM. CPU sleep/BT не используются.

Для согласованного начала при resync FIFO отключается/сбрасывается, IRQ queue
очищается при отключённом GPIO interrupt. С выключенным FIFO ожидается один DRDY:
это явно отброшенный опорный фронт (`alignment_discards`, SYNC_REFERENCE), не
измерительная запись. FIFO включается в первой половине периода после него;
проверяются deadline и отсутствие нового IRQ в этом окне. Если окно пропущено,
синхронизация отвергается, метки не угадываются. Настройки частоты/диапазонов и
питание MPU не меняются. Участок **не выдаётся за непрерывный**; ориентация теряет
готовность. До первого DRDY timeout 200 мс, ожидание только в sampler, не HTTP.

Считывается INT_STATUS, FIFO_COUNT; проверяются overflow, целое число 14-байтовых
пакетов и число IRQ-меток. FIFO может отставать от фронта: пустой FIFO допускает
ограниченное ожидание до 50 мс без удаления меток. Для снимка префикса требуется
совпадение количества полных выборок и меток; при пограничной гонке — один повтор
счётчика через 1 мс. Новые IRQ/FIFO дописывают только хвост. Старый префикс читается
ровно один раз с теми же очередными метками. Лишние метки, нехватка, частичный пакет,
ошибка чтения -> SENSOR_GAP, counters, discard/reset/resync, не угадывание меток.

Стратегия намеренно консервативна: на пограничной гонке может отбросить пригодный
участок, но не читает текущие регистры несколько раз как «пропущенные выборки».
FIFO имеет 1024 байта, около 73 выборок, не является четырёхсекундным сетевым ring.
DRDY-метка содержит задержку входа ISR; физическую задержку DLPF не убирает.
Требуется аппаратно проверить соответствие FIFO/INT конкретного MPU/клона.
WHO_AM_I/ACK недостаточны; контрольные FIFO_EN/USER_CTRL/INT_ENABLE читаются обратно.
При неподтверждённых регистрах `sensor_ok=false`, raw не выдумывается.

seq — только число **сформированных** записей. Доформировочные потери отражены
counters/событиями/временем, даже если seq непрерывен. Перед UINT32_MAX поток
пересоздаётся, опыт явно завершается. Невидимого wraparound нет.

## Независимость потребителей

Sampler core1, приоритет20, только I²C/числа/короткий state+ring mutex. Он не
сериализует JSON и не ждёт сети/LCD. Конфигурационные операции передаются ему
через очередь длины1 и фиксируются на границе записей; HTTP-handler не ждёт
30-секундную калибровку. Она — статистический автомат на новых samples.

Transport core0/priority5, pump5мс, snapshot не более8 записей под mutex, затем
unlock перед сериализацией и отправкой. Нет буфера истории на каждого клиента.
HTTPD API вызываются в HTTPD task через queue_work; не произвольным параллельным
вызовом низкоуровневого WS-send. На endpoint только один outstanding work.
WS send override делает socket send с MSG_DONTWAIT; EAGAIN/сломанный кадр закрывает
клиента, не ждёт его секунды. Socket TX имеет ограниченный TCP/lwIP budget.
ACK lease 2,5 с; UART TX free-space проверяется до записи целого COBS-кадра,
ожидание в драйвере не блокирует sampler. FIFO UART всё равно физически передаёт
без flow control; отсутствие ПК само по себе не останавливает измерение.

LCD core0/priority2, 5 Гц, только изменённые символы, не clear на каждом кадре;
строки padding ровно16 ASCII. Ошибка LCD не распространяется на AP/сенсор.
Отсутствие MPU не выключает диагностику/AP/UART.

## Бюджет внутренней RAM (без PSRAM)

| Объект | Бюджет |
|---|---:|
| ring: 832 × sizeof(sample)=48 + counters | **39944 байта** native/ESP32 ABI проверять map |
| IRQ queue:96×8 + FreeRTOS overhead | ~0,9 КБ |
| 6 endpoints (5 WS + USB), один TX max6184 | ~37,5 КБ static |
| bounded follow-up после GAP:6×410 | ~2,5 КБ static, не копия истории |
| UART COBS RX/TX/decoded scratch | ~18,6 КБ static |
| UART driver RX8192+TX8192 | ~16,5 КБ heap |
| request dedup16×644 | ~10,3 КБ static |
| events64×160 (с идентичностью stream) | ~10 КБ static |
| app state/операции | ~3 КБ |
| стеки sensor6144, LCD4096, transport7168, commands10240 | 27,6 КБ heap |
| HTTPD stack6144 + служебные FreeRTOS/Wi-Fi/idle | SDK allocation |
| bounded command queue4×pointer + до4×4097 текста | до16,5 КБ transient |
| cJSON tree/response, один dispatcher + API | ~10–25 КБ transient, зависит от запроса |
| Wi-Fi RX8 static + RX/TX dynamic16, lwIP TCP | SDK runtime, зависит от станций/сокетов |

Это **бюджет**, не обещание статической суммы «всегда свободно». Реальный запас
и четыре станции требуют нагрузки. Status возвращает free_heap, minimum_free_heap,
high-water стека каждой прикладной задачи (в ESP-IDF байты). Проверяйте минимум,
а не только текущее free. При malloc/очереди/размере — отказ/BUSY/закрытие с
reconnect, не неограниченная очередь и не malloc на каждый sample. Глубина ring
всегда832: 16,64/8,32/4,16 с при50/100/200 Гц, не менее ceil(4*rate)+1.

HTTPD max_open_sockets10, lwIP16: до5 WS (четыре записи+UI), места для служебных
сокетов и последовательной загрузки страницы. SoftAP max_connection4 **станции**;
несколько WS на станции не превращаются в отдельные Wi-Fi станции.
